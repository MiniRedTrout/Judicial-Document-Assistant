# Как перенести исправленный проект

Архив собран на основе вашего back (4).zip. Фронт, шрифт и рабочий код интеграций сохранены.

## Локальный проект Windows

1. Остановите сервер Ctrl+C, сделайте резервную копию проекта.
2. Распакуйте архив в отдельную папку.
3. Скопируйте СОДЕРЖИМОЕ папки Delo в корень вашего проекта (там находятся app, src, scripts), с заменой одноимённых файлов. Не создавайте вложенную папку Delo в существующем проекте.
4. Сохраните свой .env, .venv и storage. В этом архиве их нет.
5. Удалите старый poetry.lock в корне. Основной путь установки здесь pip. Если команда использует Poetry, сначала создайте и проверьте новый lock.
6. Удалите старые fssp_001.xml ... fssp_021.xml, лежащие прямо в tests/fixtures. Теперь они находятся в tests/fixtures/fssp вместе с labels.csv. Не удаляйте другие ваши примеры.
7. В активной .venv из корня выполните:

    python -m unittest discover -s tests -v
    python -m uvicorn app.main:app --host 127.0.0.1 --port 8000

Обновление не добавляет новых зависимостей к вашему рабочему окружению. requirements.txt переведён из UTF-16 в UTF-8, убран повтор python-dotenv; список остальных версий сохранён. Пересчёт базы для этих исправлений не нужен.

## GitLab Web IDE

Перенесите содержимое Delo в корень рабочей ветки. Включите .gitignore, .dockerignore, .env.example и .gitlab-ci.yml. Удалите старый poetry.lock и старые XML прямо в fixtures. Сверьте diff, создайте commit и merge request в main. При новых изменениях коллег объединяйте их отдельно, не заменяйте автоматически.

Ветка должна содержать tests/fixtures/fssp: 21 XML и labels.csv. .gitignore теперь разрешает эталон и docs/examples/xml_results.csv. Не загружайте .env, .venv, storage и веса моделей.
