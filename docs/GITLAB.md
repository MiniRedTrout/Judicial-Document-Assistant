# Подготовка GitLab

Архив main — каркас репозитория, а не готовое приложение. Сохраняем src, scripts, tests, data, docker; добавляем app (существующий FastAPI/frontend), docs, Compose и CI. Сам GitLab не запускает сервис от загрузки файлов; для запуска нужен сервер либо runner/deployment.

## Как перенести

1. Клонируйте командный репозиторий GitLab в отдельную папку. Это сохранит историю и ветки.
2. Создайте рабочую ветку, например integration/backend-frontend.
3. Перенесите актуальные app/src/scripts/tests из рабочего Hakaton прямо в корень клона, без лишней папки Hakaton внутри.
4. Наложите файлы этого обновления на тот же корень. Сохраните __init__.py из каркаса data/docker/tests.
5. Исходники объединяйте по изменениям команды. Не заменяйте новые файлы других разработчиков старым архивом автоматически.
6. Старый poetry.lock относится к пустому списку зависимостей: обновите его, а не оставляйте рядом с изменённым pyproject.toml.

```bash
poetry lock
poetry check --lock
```

Для установки через Poetry с OCR: poetry install -E ocr. Основной проверяемый путь инструкции — pip requirements. Lock после обновления коммитится. Не используйте старый lock. На сервере Docker устанавливает зависимости через requirements, не через этот lock.

## Что исключено

.env/пароли/ключи, .venv, .idea, storage/SQLite, логи и веса OCR исключены .gitignore/.dockerignore. .env.example содержит только пустые реквизиты. .gitignore не удаляет уже отслеживаемые секреты из истории: если они были закоммичены, отзовите секрет и разберите историю отдельно.

В корне клона перед коммитом:

```bash
git status --short
git diff --stat
```

Убедитесь, что файлы обновления и исходники присутствуют, а .env/storage/.venv не попали в изменения. Затем коммит/пуш своей ветки и merge request выполняет команда. Не делайте force push main из шаблонного README.

## CI

.gitlab-ci.yml запускает unittest на Python 3.12, отключает внешние письма/LLM. Нужен доступный runner и интернет для установки зависимостей. Он не запускает OCR на реальных сканах и не деплоит Docker. Имитация SMTP в тестах не подтверждает доставку.

## Ограничение этой подготовки

Hakaton(3).zip не был доступен при подготовке. Это набор сопутствующих файлов/конфигурации, а не объединённая финальная копия последних локальных исходников. Сначала используйте свой актуальный проект, затем наложите обновление. Для окончательной сверки и полной сборки нужен повторно загруженный актуальный архив.
