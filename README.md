# ДЭЛО — помощник по судебным документам

Прототип хакатона: загрузка судебных PDF (с текстом или сканов) и XML ФССП, извлечение сведений, сохранение результатов и выгрузка CSV по предоставленным шаблонам. Судебные акты с найденными фразами можно отправить юристу с исходным PDF во вложении.

## Реализовано

- FastAPI и браузерный интерфейс, пакетная загрузка и drag-and-drop нескольких файлов.
- PDF-экстрактор : текстовый слой либо EasyOCR; для преобразования сканов используется pdf2image + Poppler.
- XML-парсер  и общая схема полей.
- Заменяемый OpenAI-совместимый LLM API для полей PDF; конфигурация base/model/key через окружение.
- SQLite для документов, результатов, статусов и истории отправки; оригиналы на диске.
- Проверки обязательных полей, дат, сумм; явные пропуски в результатах/CSV.
- Две CSV-выгрузки по шаблонам PDF/XML, выбор отдельных документов.
- SMTP-отправка, защита от повторной отправки, отдельный отбор кандидатов для юриста.

## Структура

| Путь | Назначение |
| --- | --- |
| `app/api`, `app/services`, `app/schemas` | Backend, интеграции, SQLite, проверка и экспорт
| `app/static` | HTML/CSS/JavaScript фронта; отдельный Node-сервер не нужен
| `src/pdf_extractor`, `src/config`, `src/utils` | Модуль PDF/OCR  и конфигурация
| `src/llm/prompt.txt` | Промпт извлечения полей
| `scripts` | XML-парсер, диагностика, пересчёт сохранённых результатов
| `tests` | Автоматические тесты
| `data` | Данные/кэш; пользовательские входы и выходы не коммитятся
| `docker/Dockerfile`, `compose.yaml` | Серверный запуск
| `docs` | Инструкция, ручная проверка фронта, подготовка GitLab 
| `storage` | Создаётся при запуске: документы и SQLite, не коммитится
| `pyproject.toml`, `requirements*.txt` | Зависимости проекта и дополнительные OCR/таблицы

Основной способ установки — pip через requirements-ocr.txt; на сервере используется Docker. Устаревший poetry.lock удалён. Если команда выбирает Poetry, сначала выполните poetry lock, затем poetry install -E ocr; новый lock коммитится после проверки.

## Быстрый запуск Windows

Python 3.12 рекомендуется для нового окружения с OCR. Существующее рабочее окружение Python 3.14 не нужно удалять.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-ocr.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Скопируйте .env.example только если .env ещё не существует. Заполните POPPLER_PATH, при необходимости ключ LLM и почту. Инструкция Poppler: [docs/RUN.md](docs/RUN.md).

```powershell
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Фронт: http://127.0.0.1:8000/ ; API: http://127.0.0.1:8000/docs .

## Быстрый запуск сервера

После настройки Docker Engine + Compose и заполнения .env:

```bash
docker compose up --build -d
docker compose logs -f web
```

Poppler устанавливается внутри образа, Windows-путь не используется. Данные и веса OCR сохраняются в подключённых папках. Для доступа с рабочего компьютера используйте SSH-туннель по инструкции RUN.md.

## Примеры и текущие ограничения

В [docs/examples](docs/examples/README.md) находятся два обезличенных XML организаторов и CSV, полученный текущим парсером и экспортом. Эталон для всех 21 XML: tests/fixtures/fssp/labels.csv. Сверка:

```bash
python -m scripts.compare_xml_samples
```

На этих XML совпали 500 из 504 полей с эталоном: три расхождения относятся к записи названия улицы, одно — к повреждённому году в исходном документе. Это результат на данном наборе, а не показатель качества PDF или всех возможных XML.

PDF обрабатываются текстовым извлечением либо OCR и LLM. На сложных сканах возможны пропуски и ошибки. Неполный паспорт и противоречивые сведения отмечаются для проверки сотрудником. Исходный ответ LLM и текст сохраняются отдельно от нормализованных полей. Отбор для юриста и проверка качества извлечения — отдельные действия. Без настроенного LLM поля PDF не заполняются; XML не требует ключа.

Подключение Groq и получение письма проверены командой вручную. Автоматические тесты используют имитацию API/SMTP. Переключение на модели Яндекса предстоит проверить. Docker-сборка в этой проверке не запускалась.
